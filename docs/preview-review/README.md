# Procedure preview renders — review, 2026-08-10

Assessment of the first batch of AI procedure previews generated for the new
preview reel (the one built around the "someone else's before-and-afters"
script). Kept because the finding is easy to forget and expensive to rediscover.

## Verdict

| Render | Usable | Why |
|---|---|---|
| `hero-advisor` | **Yes** | Large, clearly legible change. Identity holds, hair stays dark, reads younger. |
| `hero-rhinoplasty` | No | Change is not localised to the nose. |
| `hero-facelift` | No | Change is not localised to the jaw. |
| `hero-eyelid` | No | Marginal localisation, far too weak to read at reel speed. |

## What was measured

All five images were normalised to a common head width and head-top row, then
cropped to the rectangle every image covers — so differences below are real
change, not framing drift. Mean per-pixel difference against `hero-before`,
measured inside three anatomical boxes (see `crop-regions.png`):

| Render | nose | eyes | jaw |
|---|---|---|---|
| Rhinoplasty | 8.84 | **10.15** | 5.86 |
| Facelift | 10.66 | 10.53 | **11.37** |
| Blepharoplasty | 8.53 | **9.94** | 5.57 |
| Advisor | 52.25 | 54.46 | **79.81** |

**The rhinoplasty render changed the eyes more than the nose.** The facelift's
jaw moved 7% more than its own nose — inside the noise floor. The generator
re-synthesised the entire portrait each time rather than editing one region, so
what little procedure-specific signal exists is buried in global resample noise.

This is why the renders "look like nothing changed": in any meaningful sense,
nothing did.

## Consequence for the reel

Only the beat built on *"Try a different procedure. Change your mind. Change it
back."* depends on these. Every other beat runs on `hero-before` +
`hero-advisor`, which are good.

**When re-generating, use a masking / inpaint workflow** — paint the region,
edit only inside it. Asking a full-frame model nicely to preserve everything
outside the nose did not work and is not expected to.

Secondary finding: all 2K renders show *more* visible pigmentation and fine
lines than the source, because regeneration invents skin texture. Left
unchecked, the "afters" have worse skin than the "before".

## Aligned assets

`public/portraits/hero-*.png` — five images, **1218x1601**, pixel-locked to a
common frame. Any two can be cross-faded or wipe-switched and only the face
changes. Generated by `align.py` (which also prints the per-region numbers
above).

Alignment parameters: target head width 900px, anchor at (617, 77) within the
cropped frame. **New renders must be run through `align.py` before use** —
the generator's framing drifts between runs and will not match otherwise.
